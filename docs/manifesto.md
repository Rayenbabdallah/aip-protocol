# The AIP Manifesto

> Agent Interaction Protocol · The Manifesto · 2026

## APIs Move Data.

**AIP moves work.** This is the manifesto for a new form of agent interaction — one built not around data exchange, but around commitment, coordination, and the nature of work itself.

---

### 01. Every agent today is *alone.*

We have built thousands of AI agents. We have made them capable of reasoning, writing, coding, deciding. We have given them memory and tools and access to the world.

And then we left them in isolation.

Each agent is an island. It knows what it knows. It does what it does. When it needs something it cannot do, it fails — or calls an API and pretends that's collaboration.

**It is not collaboration. It is data retrieval dressed up as intelligence.**

> The internet connected *machines.*  
> AIP connects *minds.*

---

### 02. The problem is *philosophical,* not technical.

We built agents on top of APIs. And APIs were built for a different world — a world where one machine had a resource and another machine wanted it. Request. Response. Done.

That model is wrong for agents. Agents don't exchange resources. **Agents do work.** And work is different from data in every way that matters.

Work has intent. Work has uncertainty. Work takes time. Work can fail. Work involves two parties who both have stakes. Work requires negotiation, commitment, and trust.

No API has ever modeled any of that. So we built agents on a foundation that was never designed for them — and we wonder why they feel hollow.

---

### 03. Work needs a *new form.*

Not a better API. Not a smarter wrapper around HTTP. A new form — designed from the ground up around the nature of agent work.

A form where the atom of interaction is not a request but a **Pact** — a mutual commitment between two agents who both understand what is being asked, what it will cost, and what happens if it fails.

A form where negotiation is native — where an agent can say *not like that, but like this* before committing. Where uncertainty is declared, not hidden. Where the output of work carries proof that the work was real.

A form where agents are not tools to be called. **They are workers to be engaged.**

> Agents are not tools.  
> They are *workers.*  
> Workers need a way to find each other,  
> commit to each other,  
> and *build together.*

---

### 04. We invented the *language.*

Every paradigm needs a vocabulary. TCP/IP has packets and headers. HTTP has requests and responses. The web has pages and links.

AIP has eight words. Each one was chosen because it carries exactly the weight of what it describes — no more, no less.

#### The Eight Words
* **Bid** — the initiating gesture
* **Echo** — the bid returning reshaped
* **Pact** — committed work, the atom of AIP
* **Flow** — the pact in motion
* **Spun** — a child pact born mid-flow
* **Seal** — commitment honored
* **Drift** — commitment broken
* **Yield** — the verified output

These are not technical terms. They are a new way of thinking about what happens when two agents decide to work together. Read them aloud and you can feel the lifecycle of a piece of work — from reach to resolution.

**No other protocol has a narrative. AIP does.**

---

### 05. This is *inevitable.*

Agents are multiplying. Every week there are more of them — more capable, more autonomous, more connected to the world. The question of how they coordinate is not a research question. It is an engineering emergency.

Right now, every agent framework is solving this problem privately, incompatibly, and badly. LangChain agents cannot talk to AutoGen agents. CrewAI workflows cannot delegate to Claude. Every team reinvents coordination from scratch.

That will not last. The pressure toward a standard is immense. **The only question is who defines it — and whether they define it well.**

AIP is our answer. Not because we want to own the standard. Because we believe the standard must be built around the right idea — and the right idea is that agents coordinate work, not data.

---

### 06. AIP belongs to *everyone.*

AIP is an open protocol. Not open source with a corporate owner. Not open until it matters. **Open as a first principle.**

The spec is public. The governance is transparent. Any agent, any framework, any company can implement AIP. The network grows stronger with every implementation — not weaker.

We author AIP. We do not own it. The same way Tim Berners-Lee authored the web and gave it to the world — not because he was naive, but because he understood that the value of a protocol is proportional to its adoption, and adoption requires trust, and trust requires openness.

**AIP's success is measured in agents connected, not in revenue captured.**

> *An agent makes a Bid.*  
> The receiver Echos back.  
> A Pact forms. It flows.  
> It Seals — or Drifts.  
> *The network learns.*
